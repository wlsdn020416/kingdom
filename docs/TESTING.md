# 테스트와 검증

모든 명령은 저장소 루트에서 실행한다. 아래 명령은 2026-10-25에 Godot 4.7.2 (macOS, `/opt/homebrew/bin/godot`)에서 실제로 실행해 확인했다.

## 현재 가능한 검증

### 전체 실행 (작업 완료 전 필수)

```sh
sh tests/run_all.sh
# 다른 Godot을 쓰려면: GODOT=/path/to/godot sh tests/run_all.sh
```

먼저 `godot --headless --path . --import`로 프로젝트를 다시 훑은 뒤(새 `class_name` 등록) 세 검사를 순서대로 실행하고 `PASS  <이름>` / `FAIL  <이름>`을 출력한다. 하나라도 실패하면 종료 코드 1. 약 25초.
로그는 `$TMPDIR/kingdom-tests/*.log`에 남는다.

통과 조건은 **종료 코드 0 + 결과 줄 `<이름> PASS` + 로그에 `SCRIPT ERROR` 없음** 세 가지 모두다.
Godot은 `--script`로 실행한 파일의 파싱 오류나 실행 중 스크립트 오류가 있어도 종료 코드 0으로 끝날 수 있기 때문이다.
또 엔진이 죽으면 프로세스가 멈출 수 있어서 검사마다 제한 시간을 둔다(macOS에 `timeout`이 없어 `perl alarm` 사용).

### 어디에 테스트를 추가하나

바닥 타일 적용 검증도 스모크 테스트에 포함된다. 모든 지형·변형의 아틀라스 칸, 물 변형 전체의 충돌과 육지의 비충돌, 실제 월드의 지형별 타일 선택·변형 사용을 확인한다. 반복 질감·경계·낮과 밤의 가독성은 직접 플레이로 확인한다.

생성물은 8종 그림의 존재·NONE 칸 투명 여부, 기존 28×28 충돌 유지, 32×48 그림의 바닥 정렬도 검사한다. 키가 커진 나무의 캐릭터 겹침·바이옴별 가독성은 직접 플레이로 확인한다.

기본 검은 스모크 테스트의 실제 좌클릭 타격과 함께 공격 방향·궤적 재생 시작, 원본 규격의 PNG 로딩, 버튼을 놓은 뒤 재생 시간 내 종료도 확인한다. 검의 회전·몸과의 겹침·궤적 방향과 밝기는 직접 플레이로 확인한다.

체력바는 로직 테스트에서 0·음수·아주 적은 체력·최대치 초과 비율의 채움 폭을 검사한다. 스모크 테스트는 채집물 피격 후 표시, 4초 뒤 숨김(실제 체력 유지), 파괴 후 제거, HUD의 픽셀아트 스타일 연결을 확인한다. 나무·몬스터와의 겹침, HUD 글자·밤 가독성은 직접 플레이로 확인한다.

적 그래픽은 스모크 테스트에서 8종의 모든 프레임 존재·행 번호 중복·체력바용 최상단 좌표, 이동 프레임·좌우 반전·정지, 기존 원형 충돌·피해·피격 표시를 확인한다. 실제 보행·호흡, 그림과 충돌의 체감 크기, 체력바와의 겹침·밤 가독성은 직접 플레이로 확인한다.

건설물은 스모크 테스트에서 5종·제작대 0~3단계 그림의 존재·칸 중복·체력바 높이, 32×32 충돌·피해 유지, B 메뉴의 동일 아틀라스 아이콘, 제작대 업그레이드 시 그림 전환을 확인한다. 실제 설치 미리보기·연속 배치 이음새·체력바·밤 가독성은 직접 플레이로 확인한다.

장비·소지품 창은 스모크 테스트에서 실제 I 입력으로 열기·공격 차단, 6부위·격자 표시, 장비 호버의 설명·부위 강조, 클릭 장착·해제·무기 해제 금지, 재료 스택·용량·변경 갱신, 툴팁 화면 안 배치, Esc 닫기·공격 복구를 검사한다. 1280×720 실제 Godot 렌더링으로 기본 배치·재료 탭·호버 설명창을 확인하고, 마우스 이벤트로 탭 전환·호버·장착·해제·닫기도 확인했다. 게임 안에서의 지속적인 마우스 조작과 작은 창에서의 가독성은 직접 플레이로 확인한다.

HUD는 스모크 테스트에서 재화 기본 접힘·클릭 펼침·가방과 창고 수량 구분·아이콘 및 이름 툴팁 연결·다시 접을 때 패널 높이 복구·낮과 밤 절반의 시계 바늘 위치를 확인한다. 1280×720 실제 Godot 렌더링에서 기본 상태·재화 펼침·밤 배치를 확인했다. 시계 움직임의 체감, 툴팁·버튼의 마우스 조작은 사용자가 `godot --path .`로 직접 확인 필요.

스킬바는 스모크 테스트에서 아틀라스 규격·7종 고유 아이콘의 비투명 그림·대시/빈칸 안내·실제 장비 착용 후 1~4번 설명 갱신·대시 간격과 마지막 슬롯의 화면 안 배치를 확인한다. 1280×720 실제 Godot 렌더링으로 미장착·스킬 4종 장착·다른 스킬 구성·쿨타임 덮개/남은 초 배치를 확인했다. 실제 단축키 조작감과 호버 설명, 쿨타임 복귀의 가독성은 사용자가 `godot --path .`로 직접 확인 필요.

- 노드 없이 돌아가는 규칙(`WorldGenerator`, `Equipment`, `Loot`, `Balance` 함수 등) → `tests/logic_test.gd`에 `_test_xxx()` 함수 추가.
  `--script`로 실행되어 **오토로드(`Events`, `Session`)와 입력 액션이 없다.** 이것들을 쓰는 코드는 여기서 테스트할 수 없다.
- 노드·신호·물리가 얽힌 흐름 → `tests/smoke_test.gd`에 `_check(조건, "설명")` 추가. 실제 게임 씬이 오토로드와 함께 돈다.
- 확인 항목 이름은 한국어로 "무엇이 어떻게 되어야 하는지"를 쓴다.

## 무기·공격 그래픽 검증

기존 스모크 테스트는 현재 무기 5종·폭탄의 그림 정의, 8프레임·고유 행·캔버스 끝 잘림 없음·공격/회복 자세 차이, 투사체 6종×4프레임과 효과 5종×6프레임 존재, 활의 무기 자세·몸 반동 진행, 공격 방향 유지·무기 교체 시 종료·휩쓸기 각도에 따른 궤적 확장을 확인한다. 실제 근접 피해·0.12초 검 궤적·채집 흐름은 유지해서 검사하며, 표시 전용 투사체의 피해 중복 없음과 폭발 그림의 무피해·수명 종료도 확인한다. NET TEST는 상대의 장착 무기·공격 모션과 아군 화염탄의 표시 전용 복제본 전달을 확인한다.

실제 Godot 렌더링으로 무기별 대기·공격·회복, 왼쪽·위쪽 조준과 투사체·폭발 프레임을 확인했다. 공격의 연속적인 손맛, 캐릭터·나무·적과의 겹침, 밤 가독성은 사용자가 `godot --path .`로 직접 확인 필요.

## 효과음 검증

기존 `sh tests/run_all.sh` 안에서 검사한다. 스모크 테스트는 43종·168개 WAV 로딩, 실제 2D 오디오 믹서의 무음이 아닌 출력(`AudioEffectCapture`, headless Dummy에서도 동작), 먼 소리 제외·같은 종류 중복 제한·음원 노드 상한·게임용 난수 미소비·일시정지 중 UI 재생·패널 열고 닫기·실패 건설의 성공음 없음·동기화 상태 적용 시 재발음 없음·이동 거리 기반 발소리·대시/치유/멸망 재생 경로를 확인한다. 접속 테스트는 호스트/참가자 행동음 전달, 월드 결과음 전달, 내 행동음의 반송 없음, 참가자의 허용 목록 밖 효과음 거부를 확인한다.

실제 스피커·헤드폰의 음색, 여러 효과음의 체감 음량, 좌우·거리감, 반복 피로도는 사용자가 `godot --path .`로 직접 확인 필요. Space·좌클릭·장비 스킬·채집·건설·R 수리·I/K/M/T 열고 닫기·밤 전환을 확인한다. 전략회의에서 핑을 찍을 때도 소리가 들리고, 재개 전에는 월드 소리가 멈춰 있어야 한다.

## Godot 명령의 함정 (확인됨)

- `godot --check-only --script res://x.gd`는 쓰지 않는다. 오토로드를 몰라 정상 코드도 `Identifier not found: Events`로 실패하고, 실제 파싱 오류가 있어도 종료 코드 0이다.
- `ResourceLoader.load()`로 씬을 불러오면 `ext_resource` 경로가 깨져도 씬이 반환된다. 그래서 `check_scripts.gd`가 의존 파일 존재를 따로 확인한다.
- 실행 중인 스크립트 자신을 `CACHE_MODE_IGNORE`로 다시 불러오면 엔진이 signal 11로 죽는다. `check_scripts.gd`는 자기 자신을 건너뛴다.
- 새 `class_name` 파일을 만든 직후에는 전역 클래스 캐시(`.godot/global_script_class_cache.cfg`)에 없어서 다른 스크립트가 `Identifier not declared`로 실패한다. 개별 검사를 돌리기 전에 `godot --headless --path . --import`를 한 번 실행한다(`run_all.sh`는 자동으로 함).
- `Engine.time_scale`을 바꾼 테스트는 끝나기 전에 1.0으로 되돌린다.

## 확인할 수 없는 것 (현재 한계)

- 렌더링 결과(색, 배치, 스프라이트), 실제 키보드·마우스 입력, 프레임 성능.
- 멀티플레이: 네트워크 코드가 아직 없다.
- 장시간 플레이(여러 날, 보스 밤) 밸런스.

## Steam 연동 확인 (사람이 직접, D-016)

자동 테스트는 headless라 Steam을 켜지 않는다. Steam 클라이언트에 로그인한 상태에서 `godot --path .`로 실행하고 시작 화면의 멀티플레이 팝업에서 "Steam:" 줄을 본다. 초대는 두 Steam 계정·두 컴퓨터에서 둘 다 게임을 켠 뒤, 호스트가 `Steam 방 만들기` → 팝업의 온라인 친구 목록에서 `초대`(오버레이가 뜨면 `친구 초대`) → 참가자가 Steam 채팅의 초대 수락 순서로 확인한다.

- `Steam: <내 Steam 이름> (App 480)` → 연결 성공. Steam 친구 목록에 "Spacewar 플레이 중"으로 보인다.
- `Steam: 연결 실패: ...` → Steam 클라이언트가 꺼져 있거나 로그아웃 상태.
- `Steam: GodotSteam을 불러오지 못함` → `addons/godotsteam/`이 없거나 라이브러리를 못 불러옴. macOS에서 보안 경고가 떴다면 시스템 설정 > 개인정보 보호 및 보안에서 허용.
- Steam 없이 실행하려면 `godot --path . -- --no-steam`.

## 멀티플레이 확인 (사람이 직접, D-017)

- 한 기기에서: 창 두 개를 띄운다(`godot --path . -- --no-steam` 두 번). 한쪽은 "개발용 IP" → 열기, 다른 쪽은 참가 → 호스트가 "시작". 서로의 캐릭터가 움직이는지 본다.

## K 패시브 연출 검사

스모크는 패시브55개가 연출 분류에 포함되는지, 14계열×8프레임의 내용·변화·가장자리, 수명 뒤 해제와 HP/XP 불변, 같은 프레임 대규모 요청의 표시 상한, 실제 재생 회복·최후의 저항·대시 강화·회오리 발동 신호, 배우기 성공 시 노드 습득 파동을 확인한다. 삭제된 노드의 검사는 Variant로 받아 is_instance_valid로 판별한다(해제된 객체를 클래스 타입으로 변환할 수 없는 엔진 동작). 전체 검사 명령은 기존 sh tests/run_all.sh다.

실제 Godot에서 K 습득 파동, 회오리의 게임 내 원형 범위, 최후의 저항, 14종 이펙트 도감을 렌더링했다. 사용자는 godot --path .에서 K를 배운 후 연속 전투·회복·채집·건설, 밤/다인 전투 가독성·연출 빈도를 직접 확인한다. 대상은 장비 액티브가 아니라 K 패시브이며 상시 능력치 노드는 습득 표시를 사용한다.

NET TEST의 음원은 실제 비신뢰 RPC를 사용하므로 단발 패킷 도착을 후속 검사의 시작 조건으로 가정하지 않는다. 호스트는 참가자의 다음 단계 활 상태가 관측될 때까지 0.1초 간격으로 upgrade/rally를 재알린다. 기존 음원 수신·반송 방지·무기/장비/패시브·전투 결과의 모든 단언은 유지한다.
패시브 연출은 수명이 0.7초라 두 화면의 검사 시점이 어긋나면 놓이므로, 0.25초 뒤 확인하고 필요하면 다시 보낸다.

사용자가 `godot --path .`로 직접 확인 필요: 3일차 이후 보스 등장, 전투 효과음 대비 음악 음량, 한 곡 이상 반복 연결, T 회의 중 멈춤/재개, 아침에 살아 있는 보스, 처치·승리·멸망·타이틀 복귀. 두 Steam 계정에서 같은 조건도 확인한다.

## 월드 Y 정렬·건물끼리의 앞뒤 관계

기존 `sh tests/run_all.sh`의 스모크는 실제 main.tscn의 중첩 Y 정렬(Main·World·Objects·Kingdom·Enemies), 성·플레이어·생성물의 같은 Z, 몸·무기·장비의 객체 단위 묶음, 추가로 만든 건물끼리·성과의 공통 정렬, 바닥 뒤/공격 연출·설치 미리보기 위 레이어를 확인한다. 실제 픽셀 가림 순서는 headless로 검사하지 않는다.

재현: 같은 나무 위치에서 플레이어를 나무 기준점보다 위쪽에 두면 기존 씬은 플레이어를 항상 앞에 그렸다. 원인은 Main·중간 컨테이너·Objects의 Y 정렬이 모두 꺼져 있었기 때문이다. 수정 후 실제 Godot 렌더링에서 나무·화살탑·거인·성의 앞/뒤 플레이어와 화살탑/화염탑의 앞뒤 위치를 교환한 그림을 확인했다. 두 건물의 자식 추가 순서는 바꾸지 않았다.

사용자가 `godot --path .`로 직접 확인 필요: 나무·벽·문·생활 건물·성 뒤와 앞을 걷기, 위아래로 연속 설치한 건물끼리의 겹침, 공격/장비 모션·피격 체력바·설치 미리보기, 두 플레이어와 참가자용 적의 앞뒤. 기준은 그림 꼭대기가 아니라 월드의 배치 기준점이며 같은 Y는 기존 순서를 따른다.

사용자가 `godot --path .`로 직접 확인 필요: 3~21일차 보스별 연속 전투와 돌진 예고·좌우 이동·다인/밤 가독성, 장식과 실제 충돌의 체감. 핵 옆 E 집무실의 재료 툴팁·연속 강화·수리와 제작대 E 창에서 장비 선택/제작도 확인한다.

## 화면별 커서 직접 확인

기존 전체 검사 명령을 사용한다. 실제 OS 커서는 viewport PNG에 포함되지 않으므로 별도 PNG 렌더와 화면 전환/호버로 확인한다. `godot --path .`에서 메인 메뉴 황동 화살표 → 버튼 위 왕실 장갑 → 시드 입력 칸 기본 IBEAM → 시작 후 중앙 조준점 → 시작 화면 복귀 시 화살표 전환을 확인한다. `-- --seed=cursor-preview`로 바로 시작해도 조준점이어야 한다. 각 그림의 클릭 기준점과 실제 조준/클릭 위치, 창 밖에서 다시 들어왔을 때의 표시, OS 배율별 크기는 사용자가 직접 확인 필요.

커서 복귀 회귀 검사는 스모크 테스트에 포함한다. 테스트 소유 노드에 attach한 뒤 창 mouse_entered/focus_entered에 갱신 연결이 등록됐는지 검사하고 두 이벤트를 발생시킨다. 소유 노드 해제 후 연결 수가 원래대로 돌아와 다음 화면을 이전 씬이 덮어쓰지 않는지도 검사한다. 이는 실제 macOS 네이티브 이미지 표시를 대신하는 검사가 아니므로 사용자 창에서도 확인한다. 이전 버전으로 이미 켜 둔 게임/미리보기는 파일 변경만으로 _ready를 다시 실행하지 않으므로 재실행한다.

## 무기 전면 표시·건물 축소·야간 조명

기존 전체 검사 안에서 스모크의 로컬 무기와 NET TEST의 원격 무기가 몸/장비보다 나중 형제이고 같은 Z인지 검사해 물체 간 Y 정렬을 유지한다. 건물은 기존 한 칸 충돌·피해 확인을 유지한다. 스모크는 실제 공성탑·핵·플레이어 광원을 한밤/황혼/낮에 갱신해 건물만 감광되고 플레이어는 기존 강도이며 황혼은 절반, 낮은 0인지 검사한다. 공성70%·생활55%의 실제 그림·설치 미리보기와 체력바 정렬은 Godot 낮/밤 렌더로 확인한다. 같은 밀집 배치에서 기존 조명 수치와 완화한 조명을 비교해 과다 노출 감소도 확인했다. 연속 조작과 여러 플레이어/건물이 빽빽한 밤 가독성은 사용자가 godot --path .로 직접 확인 필요.
