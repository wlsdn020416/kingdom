# 설계 결정 기록

되돌리기 어렵거나 이유를 잊기 쉬운 결정을 적는다. 새 결정은 아래에 번호를 이어서 추가하고,
바뀐 결정은 지우지 않고 상태를 "대체됨 → D-0xx"로 바꾼다.

형식: **상태** (확정 / 임시 / 대체됨), 결정, 이유, 다시 볼 조건.

---

## D-001 기능 중심 폴더 구조 — 확정 (2026-10-25)

- 결정: `scenes/`(진입점), `src/<기능>/`(core, world, characters, combat, enemies, kingdom, gameplay, ui, 예정: multiplayer), `data/`, `tests/`, `tools/`, `docs/`. 씬과 스크립트는 기능 폴더 안에 함께 둔다.
- 이유: 기능 단위로 찾고 고치기 쉽다. 기존 코드가 이미 이 구조로 정리되어 있어 이동하지 않았다.
- `assets/`, `src/multiplayer/`는 첫 파일이 생길 때 만든다(빈 폴더 금지). `Logo.png`, `icon.png`는 아직 어디서도 참조하지 않아 루트에 그대로 두었다.
- 갱신 (2026-10-25, 사용자 결정): 루트에는 설정·안내 문서만 둔다. `Logo.png`·`icon.png`는 `assets/branding/`으로 옮기고 `icon.png`를 게임 아이콘(`config/icon`)으로 지정했다. `기획서.md`는 `docs/기획서.md`로 옮겼다.

## D-002 오토로드는 Events, Session 두 개 — 확정

- 결정: `Events`(사건 신호 모음), `Session`(시드, 직전 판 결과, 씬 전환, 입력 등록)만 오토로드. 상수·정적 함수 모음은 `class_name` + `RefCounted`.
- 이유: 전역 상태가 늘면 판 초기화와 멀티플레이 권한 관리가 어려워진다. 한 판의 상태는 `main.tscn` 아래에 두고 씬을 버려서 초기화한다.
- 다시 볼 조건: 네트워크 연결이 씬 전환을 넘어 유지되어야 할 때(로비 → 게임). 그때 `Network` 오토로드 추가를 검토한다.

## D-003 시스템 연결: setup() 주입 + Events 신호 — 확정

- 결정: 조립은 `scenes/main.gd`가 `setup()`으로 한다. 명령·조회는 직접 메서드 호출, 여러 곳이 듣는 사건은 `Events` 신호.
- 이유: 의존 관계가 `main.gd` 한 곳에 드러나고, 시스템을 테스트에서 따로 만들 수 있다. 모든 것을 신호로 하면 흐름 추적이 어려워서 섞어 쓴다.

## D-004 게임 데이터는 당분간 const Dictionary — 임시 (2026-10-25)

- 현재: `data/balance.gd`, `items.gd`, `enemies.gd`, `buildings.gd`의 `const` 딕셔너리, ID는 문자열.
- 목표: 아이템·적·건물 정의를 Resource(`class_name XxxDef extends Resource` + `.tres`)로 관리.
- 지금 전환하지 않는 이유: 항목 수가 적고(장비 13, 적 4, 건물 3) 한 파일에서 한눈에 보고 고치기 쉽다. 전환은 모든 사용처(`ItemDB.ITEMS[id]["skill"]` 등)를 바꾸는 큰 작업이라 기반 작업 범위를 넘는다.
- 전환 조건(하나라도 해당되면 한 DB씩 전환): 에디터에서 데이터를 편집해야 할 때, 스프라이트·사운드 같은 에셋을 데이터에 연결할 때(Phase 2), 항목이 한 파일에서 관리하기 어려울 만큼 늘 때.
- 전환해도 유지할 것: 문자열 ID(네트워크로 보낼 값), `data/` 위치, 정의는 읽기 전용(런타임 상태는 별도 객체).

## D-005 호스트 권한 멀티플레이 — 확정 방향, 미구현

- 결정: 호스트가 월드 상태·전투 결과·자원·게임 시간·보상 추첨·승패를 결정한다. 클라이언트는 입력과 요청만 보낸다.
- 규칙(지금부터 적용): 상태 변경은 소유 시스템의 명령 메서드를 거치고, 명령 메서드가 검증한다. 게임 규칙에 `rpc`를 섞지 않는다. 결과용 무작위는 호스트만. (`AGENTS.md` 5절)
- 미정(기획): 전용 서버 여부, 중도 참가, 호스트 이탈, 저장 소유권.

## D-006 월드는 192×192 단일 배열, 청크 로딩 없음 — 임시

- 이유: 이 크기는 `PackedByteArray` 몇 개로 충분하고 타일맵도 한 번에 그려진다. 청크는 필요성이 확인되지 않았다.
- 다시 볼 조건: 월드 크기를 크게 늘리거나, 시작 시 생성·타일맵 반영이 체감될 만큼 느려지거나, 네트워크 초기 동기화가 커질 때.

## D-007 테스트: 외부 프레임워크 없이 headless 스크립트 — 임시 (2026-10-25)

- 결정: `tests/check_scripts.tscn`(스크립트·씬 로딩), `tests/logic_test.gd`(노드 없는 규칙), `tests/smoke_test.tscn`(실제 게임 흐름), 이를 묶는 `tests/run_all.sh`.
- 이유: 현재 검사 항목이 적고, 애드온(GUT, gdUnit4)은 설치·버전 관리 부담이 있다. 결과 판정은 종료 코드 + "PASS" 줄 + `SCRIPT ERROR` 없음으로 한다(Godot은 일부 오류에도 종료 코드 0).
- 다시 볼 조건: 로직 테스트 항목이 수십 개를 넘어 파일 분리·개별 실행·실패 위치 보고가 필요할 때. 그때 GUT 또는 gdUnit4 도입을 사용자와 상의한다.

## D-008 기획 미정 사항의 임시 규칙 — 임시

프로토타입을 만들며 정한 것. 기획이 확정되면 이 항목을 갱신한다.

- 스킬바 정렬: 장비 슬롯 순서(무기 → 보조 → 머리 → 갑옷 → 신발 → 장신구). 5번째 스킬부터는 숨김.
- 월드 경계: 가장자리가 바다.
- 건설 가능 위치: 왕국 핵에서 13칸 반경(`Balance.TERRITORY_RADIUS`).
- 왕국 시작 위치: 월드 중앙.
- 밤이 끝나면 남은 침공 적은 사라짐. 플레이어는 죽으면 6초 뒤 왕국에서 부활.
- 보스: 3일마다 밤에 등장(`Balance.is_boss_night`). "최종 보스"는 아직 없음.
- 무기는 항상 하나 착용(해제 불가).

## D-010 대시는 장비가 아닌 기본 능력, Space 키 — 확정 (2026-10-25, 사용자 결정)

- 결정: 모든 플레이어가 처음부터 대시를 쓸 수 있다. Space, 쿨타임 `Balance.DASH_COOLDOWN`(2.5초). 이동 방향으로, 멈춰 있으면 조준 방향으로. 대시 중에는 피해를 받지 않는다.
- 숫자키 1~4는 계속 장비 액티브 스킬 전용이다. 대시를 주던 `dash_boots` 장비는 삭제했고 시작 장비의 신발 칸은 비어 있다.
- 기획서 6장 "회피 및 대시 기능"(미정)에 대한 결정이다. `docs/기획서.md` 반영은 사용자가 한다.
- 참고: 지금 장비 중 스킬이 있는 것은 무기·보조·갑옷·장신구 슬롯에만 있어 스킬바가 4개를 넘을 수 없다. 머리·신발 스킬 장비를 추가하면 다시 숨김 규칙(D-008)이 쓰인다.

## D-011 시작 무기는 근거리 무기 — 확정 (2026-10-25, 사용자 결정)

- 결정: 시작 무기는 `rusty_sword`(낡은 검, 피해 15, 초당 2.5회, 사거리 52px, 120° 부채꼴). 낡은 활은 상자에서 얻는 장비가 된다.
- 근거리 무기는 데이터의 `"melee": true`로 구분하고, `Melee.swing()`이 투사체 없이 즉시 판정한다. 부채꼴 안의 적은 모두 맞고 넉백, 앞의 나무·바위·광석·상자는 하나만 맞는다.
- 수치는 임시. 플레이 테스트로 조정한다.
- 시작 장비는 낡은 검 + 가죽 모자. 치유 부적(`life_charm`)은 시작 장비에서 빼고 상자에서만 나온다 (2026-10-25, 사용자 결정). 시작 스킬바는 비어 있다.

## D-009 그래픽은 코드로 그린 임시 도형 — 임시

- 타일셋은 `TilesetBuilder`가 코드로 이미지를 만들고, 캐릭터·적·건물은 `_draw()`. 색은 `Palette`·데이터의 `color`.
- Phase 2에서 타일셋은 `TilesetBuilder`의 이미지 함수만, 객체는 `_draw()`를 스프라이트 노드로 교체한다.
- 진행: 플레이어는 스프라이트로 교체됨(D-012). 왕국 핵도 `assets/kingdom/castle.aseprite`에서 내보낸 96×128 PNG로 교체됨. 바닥은 `assets/world/terrain.aseprite`에서 내보낸 288×128 PNG(32×32, 지형 9종×변형 4종)를 사용하며, 위치 해시로 변형을 선택한다. 생성물도 `assets/world/objects.aseprite`에서 내보낸 PNG(32×48, NONE 포함 9칸)로 교체됨. 적·건설 건물은 아직 도형.

- 그래픽 적용 추가: 기본 낡은 검·공격 궤적도 `assets/combat/`의 Aseprite 원본·PNG로 교체했다. 검은 32×16, 궤적은 112×112 4프레임을 0.12초 동안 재생하며 `Player._draw()`가 담당한다. 기존 즉시 타격에 맞춰 첫 프레임부터 사거리 52·120도 범위를 표시한다. 다른 무기는 기존 도형을 사용한다.

- 그래픽 적용 추가: 채집물·몬스터·건물·HUD 체력바는 `assets/ui/health_bars.aseprite`에서 내보낸 PNG로 교체했다. `HealthBarArt`는 그리기만 공유하며 체력·표시 시간은 기존 소유 시스템이 유지한다.

## D-012 캐릭터 스프라이트 형식 — 임시 (2026-10-25)

- 원본 `assets/characters/<이름>.aseprite`, 게임은 같은 폴더의 가로 한 줄 시트 `<이름>.png`(Aseprite에서 내보냄)를 쓴다.
- 한 칸 24×24, 방향 순서 정면·뒷면·오른쪽 측면, 방향마다 걷기 4칸(0·2번 칸이 서 있는 자세). 왼쪽은 측면을 좌우 반전한다. Aseprite 태그 `down`/`up`/`side`.
- Godot에서는 `AnimatedSprite2D`·`SpriteFrames` 리소스 없이 `Sprite2D.hframes`로 칸을 고른다. 칸 선택 규칙이 단순해 코드 몇 줄로 충분하기 때문이다. 공격 애니메이션 등으로 칸 규칙이 복잡해지면 `AnimatedSprite2D`로 바꾼다.
- 트윈스틱이라 캐릭터는 이동 방향이 아니라 조준 방향을 바라본다.
- 스프라이트 자체는 1배로 그리고, 화면 확대는 D-013의 카메라 줌이 맡는다.

## D-013 화면 확대는 카메라 줌 2배 — 임시 (2026-10-25, 사용자 요청)

- 결정: `main.tscn`의 `Player/Camera` `zoom = Vector2(2, 2)`. 캐릭터·타일·적·건물·투사체가 모두 화면에서 2배로 보인다. HUD(`CanvasLayer`)는 영향 없음.
- 이유: 월드 단위(`Balance.TILE`, 사거리, 속도, 충돌 크기)를 전부 2배로 바꾸는 것과 화면 결과가 같으면서 밸런스 수치를 하나도 건드리지 않는다.
- 영향: 한 화면에 보이는 범위가 가로 40→20칸, 세로 22.5→11.25칸으로 줄어든다. 밤 방어 시야가 좁다고 느껴지면 줌 값(예: 1.5)을 다시 정한다. 픽셀아트는 정수 배율일 때 가장 깔끔하다.

## D-014 바이옴·재료·제작대·테크 구조 — 확정 방향, 미구현 (2026-10-25, 사용자 결정)

기획서 3장(바이옴 종류와 분포, 지역별 난이도), 5장(건설·업그레이드), 7장(장비 제작·강화) 미정 사항에 대한 방향. `docs/기획서.md` 반영은 사용자가 한다.

- **바이옴 배치:** 왕국(월드 중앙)에서 멀수록 높은 단계 바이옴이 나오는 거리별 링. 링 경계와 링 안의 바이옴 배치는 시드 노이즈로 섞는다. 같은 단계 바이옴은 몬스터 강도도 같다.
- **바이옴 구성(우선):** 0 초원 / 1 숲·사막 / 2 설원·늪 / 3 화산. 재료 이름은 가안.
- **재료:** 일반 재료는 그 바이옴 오브젝트 채집, 희귀 재료는 그 바이옴 몬스터 드롭.
- **테크:** 레시피는 (1) 재료를 처음 획득하면 제작 목록에 나타나고, (2) 요구 제작대 단계를 만족해야 만들 수 있다. 제작대 업그레이드에는 해당 단계 바이옴의 희귀 재료가 든다.
- **제작대:** 왕국 영토 안의 공용 건물. 침공에 부서질 수 있고, **부서지면 단계까지 잃는다**.
- **재료 보관:** 나무·돌·금을 포함한 **모든 자원**은 개인 인벤토리에 들어간다. 왕국 핵 근처에 가면 공용 창고로 **자동 입고**된다. 자원을 쓸 때(건설·수리·제작)는 개인 인벤토리를 먼저 쓰고 모자라면 공용 창고에서 쓴다.
- **인벤토리 용량:** 8칸, 칸당 같은 자원 50개(`Balance.INVENTORY_SLOTS`·`STACK_SIZE`, 수치 임시). 가득 차서 못 담은 보상은 사라지고 "가득 찼다"고 알린다(임시).
- **자동 입고:** 핵 중심 4칸(`Balance.DEPOSIT_RANGE`) 안에 들어오면 가방 자원 전부가 창고로 간다. 플레이어 시작·부활 지점도 이 안이다.
- **사망:** 개인 인벤토리의 자원과 장비 가방(`Equipment.bag`)이 **모두 사라진다**. 떨어뜨리지 않으며 되찾을 수 없다. 착용 중인 장비는 남는다(임시 해석). 예비 장비는 왕국에 짓는 **장비 상자** 건물에 보관한다.
- **제작대 개수:** 하나만 지을 수 있다. 부서지면 단계가 사라지고 처음(0단계)부터 다시 짓는다.
- **상자:** 그 지역(바이옴) 자원을 주는 것이 기본, 낮은 확률로 장비(테라리아식).
- **상인:** 보류 (2026-10-25, 사용자 결정 "상인 만들지 말 것"). **금:** 경험치로 대체됨 → D-015. 앞서 나온 안(1단계 링에 고정 생성, 매일 무작위 자원 판매, NPC로 장비 강화·특수 아이템)은 기록으로만 남긴다.
