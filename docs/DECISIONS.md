# 설계 결정 기록

되돌리기 어렵거나 이유를 잊기 쉬운 결정을 적는다. 새 결정은 아래에 번호를 이어서 추가하고,
바뀐 결정은 지우지 않고 상태를 "대체됨 → D-0xx"로 바꾼다.

형식: **상태** (확정 / 임시 / 대체됨), 결정, 이유, 다시 볼 조건.

---

## D-001 기능 중심 폴더 구조 — 확정 (2026-10-25)

- 결정: `scenes/`(진입점), `src/<기능>/`(core, world, characters, combat, enemies, kingdom, gameplay, ui, 예정: multiplayer), `data/`, `tests/`, `tools/`, `docs/`. 씬과 스크립트는 기능 폴더 안에 함께 둔다.
- 이유: 기능 단위로 찾고 고치기 쉽다. 기존 코드가 이미 이 구조로 정리되어 있어 이동하지 않았다.
- `assets/`, `src/multiplayer/`는 첫 파일이 생길 때 만든다(빈 폴더 금지). `Logo.png`, `icon.png`는 아직 어디서도 참조하지 않아 루트에 그대로 두었다.
- 갱신 (2026-10-25, 사용자 결정): 루트에는 설정·안내 문서만 둔다. `Logo.png`·`icon.png`는 `assets/branding/`으로 옮기고 `icon.png`를 게임 아이콘(`config/icon`)으로 지정했다. `기획서.md`는 `docs/기획서.md`로 옮겼다.

## D-002 오토로드는 Events, Session 두 개 — 확정

- 결정: `Events`(사건 신호 모음), `Session`(시드, 직전 판 결과, 씬 전환, 입력 등록)만 오토로드. 상수·정적 함수 모음은 `class_name` + `RefCounted`.
- 이유: 전역 상태가 늘면 판 초기화와 멀티플레이 권한 관리가 어려워진다. 한 판의 상태는 `main.tscn` 아래에 두고 씬을 버려서 초기화한다.
- 다시 볼 조건: 네트워크 연결이 씬 전환을 넘어 유지되어야 할 때(로비 → 게임). 그때 `Network` 오토로드 추가를 검토한다.

## D-003 시스템 연결: setup() 주입 + Events 신호 — 확정

- 결정: 조립은 `scenes/main.gd`가 `setup()`으로 한다. 명령·조회는 직접 메서드 호출, 여러 곳이 듣는 사건은 `Events` 신호.
- 이유: 의존 관계가 `main.gd` 한 곳에 드러나고, 시스템을 테스트에서 따로 만들 수 있다. 모든 것을 신호로 하면 흐름 추적이 어려워서 섞어 쓴다.

## D-004 게임 데이터는 당분간 const Dictionary — 임시 (2026-10-25)

- 현재: `data/balance.gd`, `items.gd`, `enemies.gd`, `buildings.gd`의 `const` 딕셔너리, ID는 문자열.
- 목표: 아이템·적·건물 정의를 Resource(`class_name XxxDef extends Resource` + `.tres`)로 관리.
- 지금 전환하지 않는 이유: 항목 수가 적고(장비 13, 적 4, 건물 3) 한 파일에서 한눈에 보고 고치기 쉽다. 전환은 모든 사용처(`ItemDB.ITEMS[id]["skill"]` 등)를 바꾸는 큰 작업이라 기반 작업 범위를 넘는다.
- 전환 조건(하나라도 해당되면 한 DB씩 전환): 에디터에서 데이터를 편집해야 할 때, 스프라이트·사운드 같은 에셋을 데이터에 연결할 때(Phase 2), 항목이 한 파일에서 관리하기 어려울 만큼 늘 때.
- 전환해도 유지할 것: 문자열 ID(네트워크로 보낼 값), `data/` 위치, 정의는 읽기 전용(런타임 상태는 별도 객체).

## D-005 호스트 권한 멀티플레이 — 확정 방향, 미구현

- 결정: 호스트가 월드 상태·전투 결과·자원·게임 시간·보상 추첨·승패를 결정한다. 클라이언트는 입력과 요청만 보낸다.
- 규칙(지금부터 적용): 상태 변경은 소유 시스템의 명령 메서드를 거치고, 명령 메서드가 검증한다. 게임 규칙에 `rpc`를 섞지 않는다. 결과용 무작위는 호스트만. (`AGENTS.md` 5절)
- 미정(기획): 전용 서버 여부, 중도 참가, 호스트 이탈, 저장 소유권.

## D-006 월드는 192×192 단일 배열, 청크 로딩 없음 — 임시

- 이유: 이 크기는 `PackedByteArray` 몇 개로 충분하고 타일맵도 한 번에 그려진다. 청크는 필요성이 확인되지 않았다.
- 다시 볼 조건: 월드 크기를 크게 늘리거나, 시작 시 생성·타일맵 반영이 체감될 만큼 느려지거나, 네트워크 초기 동기화가 커질 때.

## D-007 테스트: 외부 프레임워크 없이 headless 스크립트 — 임시 (2026-10-25)

- 결정: `tests/check_scripts.tscn`(스크립트·씬 로딩), `tests/logic_test.gd`(노드 없는 규칙), `tests/smoke_test.tscn`(실제 게임 흐름), 이를 묶는 `tests/run_all.sh`.
- 이유: 현재 검사 항목이 적고, 애드온(GUT, gdUnit4)은 설치·버전 관리 부담이 있다. 결과 판정은 종료 코드 + "PASS" 줄 + `SCRIPT ERROR` 없음으로 한다(Godot은 일부 오류에도 종료 코드 0).
- 다시 볼 조건: 로직 테스트 항목이 수십 개를 넘어 파일 분리·개별 실행·실패 위치 보고가 필요할 때. 그때 GUT 또는 gdUnit4 도입을 사용자와 상의한다.

## D-008 기획 미정 사항의 임시 규칙 — 임시

프로토타입을 만들며 정한 것. 기획이 확정되면 이 항목을 갱신한다.

- 스킬바 정렬: 장비 슬롯 순서(무기 → 보조 → 머리 → 갑옷 → 신발 → 장신구). 5번째 스킬부터는 숨김.
- 월드 경계: 가장자리가 바다.
- 건설 가능 위치: 왕국 핵에서 13칸 반경(`Balance.TERRITORY_RADIUS`).
- 왕국 시작 위치: 월드 중앙.
- 밤이 끝나면 남은 침공 적은 사라짐. 플레이어는 죽으면 6초 뒤 왕국에서 부활.
- 보스: 3일마다 밤에 등장(`Balance.is_boss_night`). "최종 보스"는 아직 없음.
- 무기는 항상 하나 착용(해제 불가).

## D-010 대시는 장비가 아닌 기본 능력, Space 키 — 확정 (2026-10-25, 사용자 결정)

- 결정: 모든 플레이어가 처음부터 대시를 쓸 수 있다. Space, 쿨타임 `Balance.DASH_COOLDOWN`(2.5초). 이동 방향으로, 멈춰 있으면 조준 방향으로. 대시 중에는 피해를 받지 않는다.
- 숫자키 1~4는 계속 장비 액티브 스킬 전용이다. 대시를 주던 `dash_boots` 장비는 삭제했고 시작 장비의 신발 칸은 비어 있다.
- 기획서 6장 "회피 및 대시 기능"(미정)에 대한 결정이다. `docs/기획서.md` 반영은 사용자가 한다.
- 참고: 지금 장비 중 스킬이 있는 것은 무기·보조·갑옷·장신구 슬롯에만 있어 스킬바가 4개를 넘을 수 없다. 머리·신발 스킬 장비를 추가하면 다시 숨김 규칙(D-008)이 쓰인다.

## D-011 시작 무기는 근거리 무기 — 확정 (2026-10-25, 사용자 결정)

- 결정: 시작 무기는 `rusty_sword`(낡은 검, 피해 15, 초당 2.5회, 사거리 52px, 120° 부채꼴). 낡은 활은 상자에서 얻는 장비가 된다.
- 근거리 무기는 데이터의 `"melee": true`로 구분하고, `Melee.swing()`이 투사체 없이 즉시 판정한다. 부채꼴 안의 적은 모두 맞고 넉백, 앞의 나무·바위·광석·상자는 하나만 맞는다.
- 수치는 임시. 플레이 테스트로 조정한다.
- 시작 장비는 낡은 검 + 가죽 모자. 치유 부적(`life_charm`)은 시작 장비에서 빼고 상자에서만 나온다 (2026-10-25, 사용자 결정). 시작 스킬바는 비어 있다.

## D-009 그래픽은 코드로 그린 임시 도형 — 임시

- 타일셋은 `TilesetBuilder`가 코드로 이미지를 만들고, 캐릭터·적·건물은 `_draw()`. 색은 `Palette`·데이터의 `color`.
- Phase 2에서 타일셋은 `TilesetBuilder`의 이미지 함수만, 객체는 `_draw()`를 스프라이트 노드로 교체한다.
- 진행: 플레이어는 스프라이트로 교체됨(D-012). 왕국 핵도 `assets/kingdom/castle.aseprite`에서 내보낸 96×128 PNG로 교체됨. 바닥은 `assets/world/terrain.aseprite`에서 내보낸 288×128 PNG(32×32, 지형 9종×변형 4종)를 사용하며, 위치 해시로 변형을 선택한다. 생성물도 `assets/world/objects.aseprite`에서 내보낸 PNG(32×48, NONE 포함 9칸)로 교체됨. 적·건설 건물은 아직 도형.

- 그래픽 적용 추가: 기본 낡은 검·공격 궤적도 `assets/combat/`의 Aseprite 원본·PNG로 교체했다. 검은 32×16, 궤적은 112×112 4프레임을 0.12초 동안 재생하며 `Player._draw()`가 담당한다. 기존 즉시 타격에 맞춰 첫 프레임부터 사거리 52·120도 범위를 표시한다. 다른 무기는 기존 도형을 사용한다.
- 위 기본 검 단독 표시 방식은 2026-10-26 공용 `WeaponVisual`로 대체했다. 무기 5종·폭탄을 Aseprite의 64×64·8프레임 자세로 그리며 몸의 반동을 함께 재생한다. 두 검의 0.12초 즉시 타격 궤적과 기존 피해·사거리·공격 속도를 유지한다. 아군 탄·명중·폭발도 픽셀 시트로 교체했고, 장비창의 해당 6종 아이콘은 대기 자세를 재사용한다. 기존 단독 검·궤적 원본은 보존한다.

- 그래픽 적용 추가: 채집물·몬스터·건물·HUD 체력바는 `assets/ui/health_bars.aseprite`에서 내보낸 PNG로 교체했다. `HealthBarArt`는 그리기만 공유하며 체력·표시 시간은 기존 소유 시스템이 유지한다.

- 그래픽 적용 추가: 현재 적 8종을 `assets/enemies/enemies.aseprite`에서 내보낸 시트로 교체했다. 64×64 칸, 종류별 4프레임·8fps, 가로 4열·세로 8행이며 `EnemyDB.sprite_row`·`sprite_top`으로 그림과 체력바를 배치한다. 좌우 방향은 반전하며 상·하 별도 그림은 아직 없다. 보스 외형은 현재 보스의 시각 시안이며 최종 보스 기획을 확정하지 않는다.

- 그래픽 적용 추가: B 메뉴 건설물 5종과 제작대 0~3단계를 `assets/kingdom/buildings.aseprite`·PNG로 교체했다. 32×64의 8칸이며 기본 칸은 `BuildingDB.sprite_column`, 상단은 `sprite_top`에 둔다. 실제 건물·설치 미리보기·메뉴 아이콘이 같은 그림을 사용하며 기존 비용·충돌·공격·보관·제작 규칙을 유지한다.

- 그래픽·UI 적용 추가 (사용자 요청): I 창을 왼쪽 마네킹 6부위와 오른쪽 장비·재료 탭의 격자 가방으로 바꿨다. 장착 부위 강조·호버 설명·재료 스택 수량을 제공하며, 마네킹·슬롯·재료 아이콘을 Aseprite로 제작했다. 장비 개별 아이콘은 보류하고 이름으로 표시한다. 기존 장비 가방과 재료 인벤토리의 분리·용량·장착 규칙은 유지하며 새 칸 제한을 만들지 않는다.

## D-012 캐릭터 스프라이트 형식 — 임시 (2026-10-25)

- 원본 `assets/characters/<이름>.aseprite`, 게임은 같은 폴더의 가로 한 줄 시트 `<이름>.png`(Aseprite에서 내보냄)를 쓴다.
- 한 칸 24×24, 방향 순서 정면·뒷면·오른쪽 측면, 방향마다 걷기 4칸(0·2번 칸이 서 있는 자세). 왼쪽은 측면을 좌우 반전한다. Aseprite 태그 `down`/`up`/`side`.
- Godot에서는 `AnimatedSprite2D`·`SpriteFrames` 리소스 없이 `Sprite2D.hframes`로 칸을 고른다. 칸 선택 규칙이 단순해 코드 몇 줄로 충분하기 때문이다. 공격 애니메이션 등으로 칸 규칙이 복잡해지면 `AnimatedSprite2D`로 바꾼다.
- 트윈스틱이라 캐릭터는 이동 방향이 아니라 조준 방향을 바라본다.
- 스프라이트 자체는 1배로 그리고, 화면 확대는 D-013의 카메라 줌이 맡는다.

## D-013 화면 확대는 카메라 줌 2배 — 임시 (2026-10-25, 사용자 요청)

- 결정: `main.tscn`의 `Player/Camera` `zoom = Vector2(2, 2)`. 캐릭터·타일·적·건물·투사체가 모두 화면에서 2배로 보인다. HUD(`CanvasLayer`)는 영향 없음.
- 이유: 월드 단위(`Balance.TILE`, 사거리, 속도, 충돌 크기)를 전부 2배로 바꾸는 것과 화면 결과가 같으면서 밸런스 수치를 하나도 건드리지 않는다.
- 영향: 한 화면에 보이는 범위가 가로 40→20칸, 세로 22.5→11.25칸으로 줄어든다. 밤 방어 시야가 좁다고 느껴지면 줌 값(예: 1.5)을 다시 정한다. 픽셀아트는 정수 배율일 때 가장 깔끔하다.

## D-014 바이옴·재료·제작대·테크 구조 — 확정 방향, 미구현 (2026-10-25, 사용자 결정)

기획서 3장(바이옴 종류와 분포, 지역별 난이도), 5장(건설·업그레이드), 7장(장비 제작·강화) 미정 사항에 대한 방향. `docs/기획서.md` 반영은 사용자가 한다.

- **바이옴 배치:** 왕국(월드 중앙)에서 멀수록 높은 단계 바이옴이 나오는 거리별 링. 링 경계와 링 안의 바이옴 배치는 시드 노이즈로 섞는다. 같은 단계 바이옴은 몬스터 강도도 같다.
- **바이옴 구성(우선):** 0 초원 / 1 숲·사막 / 2 설원·늪 / 3 화산. 재료 이름은 가안.
- **재료:** 일반 재료는 그 바이옴 오브젝트 채집, 희귀 재료는 그 바이옴 몬스터 드롭.
- **테크:** 레시피는 (1) 재료를 처음 획득하면 제작 목록에 나타나고, (2) 요구 제작대 단계를 만족해야 만들 수 있다. 제작대 업그레이드에는 해당 단계 바이옴의 희귀 재료가 든다.
- **제작대:** 왕국 영토 안의 공용 건물. 침공에 부서질 수 있고, **부서지면 단계까지 잃는다**.

- **사망:** 개인 인벤토리의 자원과 장비 가방(`Equipment.bag`)이 **모두 사라진다**. 떨어뜨리지 않으며 되찾을 수 없다. 착용 중인 장비는 남는다(임시 해석). 예비 장비는 왕국에 짓는 **장비 상자** 건물에 보관한다.
- **제작대 개수:** 하나만 지을 수 있다. 부서지면 단계가 사라지고 처음(0단계)부터 다시 짓는다.
- **상자:** 그 지역(바이옴) 자원을 주는 것이 기본, 낮은 확률로 장비(테라리아식).
- **상인:** 보류 (2026-10-25, 사용자 결정 "상인 만들지 말 것"). **금:** 경험치로 대체됨 → D-015. 앞서 나온 안(1단계 링에 고정 생성, 매일 무작위 자원 판매, NPC로 장비 강화·특수 아이템)은 기록으로만 남긴다.

## D-016 Steam 연동: GodotSteam GDExtension 도입 — 확정 (2026-10-25, 사용자 결정)

- 결정: 출시·멀티플레이 접속은 Steam으로 한다. Steam 기능(로그인 정보, 로비·초대, 중계 서버를 쓰는 P2P)은 GodotSteam GDExtension으로 쓴다. "GDScript만, 외부 애드온 없음" 규칙(AGENTS 1·11절)에서 이것만 예외로 한다.
- 버전: GodotSteam 4.23.2 GDExtension (Godot 4.4 이상, Steamworks SDK 1.65, MIT). 받은 곳: codeberg.org/godotsteam/godotsteam 릴리스 `v4.23.2-gde`. SteamMultiplayerPeer가 들어 있어 Godot 멀티플레이 API(RPC, MultiplayerSynchronizer)를 그대로 Steam 위에서 쓸 수 있다.
- 넣은 것: `addons/godotsteam/`에 macOS(universal)·Windows 64비트·Linux 64비트 라이브러리, `godotsteam.gdextension`, 라이선스. 안드로이드·32비트 파일은 뺐다(약 97MB → 30MB).
- 고친 것: 받은 `godotsteam.gdextension`의 macOS 경로가 실제 파일명(`.universal.dylib`)과 달라 고쳤다. 빠진 플랫폼 줄도 지웠다.
- 뺀 것: 에디터 자동 업데이트 플러그인(`godotsteam_plugin.gd`, `editor/`). 에디터를 열 때 인터넷에서 버전을 확인하고 `addons/` 폴더를 통째로 바꾸므로, 버전 교체는 사람이 이 결정 기록을 갱신하며 한다.
- App ID: 개발 중에는 Valve 테스트 앱 480(Spacewar). 자체 App ID를 받으면(Steam Direct 등록) `SteamService.APP_ID`만 바꾼다. `steam_appid.txt`는 쓰지 않는다(`steamInitEx(APP_ID)`로 전달).
- 구조: `src/multiplayer/steam_service.gd`(`SteamService` 노드)를 오토로드 `Session`이 자식으로 소유한다. 새 오토로드는 만들지 않았다(D-002 유지). Steam 싱글턴은 `Engine.get_singleton("Steam")`으로 찾아서, GodotSteam이 없거나 Steam이 꺼져 있어도 게임과 테스트가 돈다. headless 실행과 `-- --no-steam` 인자에서는 초기화하지 않는다.
- 확인 상태: 자동 테스트(headless)는 Steam을 끈 채로 통과. 실제 Steam 로그인 연결은 사람이 `godot --path .`로 시작 화면 멀티플레이 팝업의 "Steam:" 줄을 보고 확인해야 한다.
- 다시 볼 조건: GodotSteam 버전 교체, Godot 버전 교체(4.4 미만 불가), 자체 App ID 발급, 다른 플랫폼(EOS 등) 추가 검토.

## D-017 멀티플레이 구조와 단계별 범위 — 임시 (2026-10-25)

- 방식: 호스트 권한(D-005). Godot 고수준 멀티플레이(SceneMultiplayer, RPC)를 쓰고, 연결 객체만 바꿔 끼운다. 실제 플레이는 Steam 로비 + SteamMultiplayerPeer(D-016), 개발·자동 테스트는 IP 직접 접속(ENetMultiplayerPeer, 포트 24680). 참가자끼리는 직접 잇지 않고 호스트를 거친다.
- 인원: 최대 4명(`NetSession.MAX_PLAYERS`). Steam 방은 친구 공개, 초대는 Steam 오버레이로. 게임을 켠 채 초대를 수락하거나, 꺼진 상태에서 수락해 "+connect_lobby"로 실행돼도 들어온다.
- 구조: `NetSession`(접속·명단·시작, `Session`의 자식이라 씬이 바뀌어도 유지)과 게임 씬의 `PlayerSync`(이름 "PlayerSync", 경로가 모두에게 같아야 RPC가 닿음). 새 오토로드는 없다(D-002 유지). RPC는 `src/multiplayer/`에만 있다.
- 시작: 호스트가 시작 화면 멀티플레이 팝업의 "시작"을 누르면 그 시드로 모두 게임 씬을 연다. 각자 시드로 같은 월드를 만든다. 모두 씬을 불러왔다고 호스트에 알리면 호스트가 동기화를 시작시킨다(늦게 불러온 쪽에 RPC가 먼저 도착하는 문제 방지).
- 1단계 범위(이번): 각자 자기 캐릭터 이동을 결정하고(이동은 호스트 권한 목록에 없음), 위치·조준·애니메이션 칸을 초당 20번 보낸다(unreliable_ordered). 상대 캐릭터는 겉모습만 있는 `RemotePlayer`로 보여주고 부드럽게 따라간다. 참가자 쪽은 적을 만들지 않는다.
- 2단계(완료): 적·웨이브·낮밤·왕국 핵·멸망은 호스트만 계산한다(`CombatSync`).
  - 호스트 → 참가자: 적 모습 초당 10번(참가자는 `EnemyPuppet`으로 그리기만), 적 죽음, 보스 탄(참가자 화면에 같은 탄을 만들고 맞았는지는 각자 판정), 낮밤 시간(`DayNight.follows_host`), 핵 체력(`Core.set_synced_hp`), 처치 보상, 멸망 화면.
  - 적은 "player" 그룹(로컬 Player + `RemotePlayer`) 중 가장 가까운 살아 있는 플레이어를 노린다. `RemotePlayer`가 맞으면 주인에게 피해를 보내고, 무적·보호막·사망은 주인 화면이 정한다. 배회 적은 아무 플레이어 주변에나 나온다.
  - 참가자의 공격: 자기 화면에서 그대로 실행(채집은 각자)하고, `Player.attacked`(탄·휘두르기·함성)를 호스트에 보낸다. 호스트는 그 사람 위치에서 4칸 넘게 떨어진 요청은 버리고, 나머지를 `hits_world = false`로 자기 적에게만 다시 실행한다. 피해를 준 사람(`Enemy.killed_by` = peer id)이 막타 경험치·희귀 재료를 받는다.
  - 참가자의 핵 수리·N(밤으로)은 호스트에 요청한다. 호스트가 나가면 참가자는 시작 화면으로 돌아가 이유를 본다.
- 2단계의 임시 한계: 참가자가 보낸 공격의 피해 값은 믿는다(위치만 검사). 참가자의 약탈자 패시브는 호스트가 몰라 희귀 재료 확률 보너스가 빠진다. 수리 비용은 참가자 화면에서 낸다.
- 3단계(완료, 2026-10-25): 월드·왕국 변경은 호스트만 한다.
  - 나무·바위·광석·상자(`WorldSync`): 참가자 화면의 공격은 월드를 건드리지 않는다(`Player.hits_world = false`). 호스트가 다시 실행한 참가자 공격이 오브젝트를 부수고, 채집량·상자 보상을 `Main.rng`로 굴려 그 사람에게 보낸다. 오브젝트 체력·파괴는 모두에게 보낸다. 상자 열기(E)는 호스트에 요청하고, 호스트는 그 사람 위치에서 2칸 안의 상자만 연다.
  - 왕국(`KingdomSync`): 건설·철거·장비 상자 맡기기·꺼내기·제작·제작대 업그레이드·핵 수리·창고 입고를 호스트에 요청하고, 호스트는 같은 명령 메서드로 검증·적용한다. 창고·건물(체력·단계·보관 장비)·알게 된 재료는 바뀔 때 통째로 보낸다(최대 초당 5번). 참가자 화면에 따라 그린 적 탄은 내 캐릭터만 맞히고 건물·핵에는 피해를 주지 않는다.
  - 경험치: 채집·제작한 사람에게 간다. 새 레시피 공개는 호스트가 정하고 참가자는 받은 상태로 알림을 본다.
- 3단계의 임시 한계: 개인 가방·장비 가방·경험치는 아직 각자 가진다. 참가자는 요청에 가방 내용을 실어 보내고, 호스트는 그 값으로 비용을 계산해 뺄 양을 돌려준다(가방 값은 믿는다). 풍요로운 손 보너스는 받는 사람 화면에서 더한다. 화살탑은 호스트에서만 쏜다. 게임 도중 참가·재접속 미지원.
- 검증: `tests/net_test.tscn`을 호스트·참가자 두 headless 프로세스로 동시에 띄운다(`run_all.sh`의 NET TEST, 실행마다 다른 포트). 접속·명단·같은 시드·상대 생성·위치 전달, 호스트의 적이 참가자를 때림, 참가자의 공격이 호스트의 적을 죽이고 보상을 받음, 죽은 적이 사라짐, 핵 체력·밤 전달을 확인한다. Steam 경로는 두 Steam 계정으로 사람이 확인한다.

## D-018 공유 지도: 탐험 칸·핑 동기화 — 임시 (2026-10-26)

- 기획: 플레이어 간 지도 탐험 정보 실시간 공유(기획서 8장 확정 사항).
- 탐험 칸: 각자 자기 캐릭터 주변을 밝힌다(`World.reveal`). 새로 밝힌 칸을 0.25초마다 모아 칸 번호 배열로 보내고, 참가자 것은 호스트를 거쳐 나머지 참가자에게 간다(`MapSync`, D-017의 "참가자끼리는 직접 잇지 않는다"). 받은 칸은 `World.mark_explored()`로 표시하고 다시 보내지 않는다. 동기화가 시작되기 전에 밝힌 칸도 모아 두었다가 시작 신호 뒤에 보낸다.
- 핑: 호스트의 `MapState.pings`가 원본이다. 참가자의 핑 찍기·지우기는 호스트에 요청하고, 호스트는 핑 목록이 바뀔 때마다 전체를 모두에게 보낸다(`MapState.set_pings`). 전략회의 창은 `MapSync.add_ping·clear_pings`를 부른다.
- AGENTS 5절 1항의 "탐험은 호스트가 결정"에서 벗어나는 임시 규칙: 탐험은 각자의 이동(각자 결정, D-017)에서만 나오고 지도 표시 외의 결과가 없어서, 호스트는 받은 칸을 검사하지 않고 전한다. 탐험이 보상·진행에 영향을 주게 되면 호스트가 `RemotePlayer` 위치로 직접 밝히는 방식으로 바꾼다.
- 범위 밖: 전략회의의 전원 일시정지·준비 완료(지금은 각자 화면만 멈춘다), 도중 참가자에게 지금까지의 탐험 전체 보내기.
- 검증: NET TEST에서 참가자가 다녀온 곳이 호스트 지도에, 호스트가 다녀온 먼 곳이 참가자 지도에 탐험되는지, 참가자의 핑이 호스트를 거쳐 양쪽에 보이는지 확인한다.

## D-019 전략회의 전원 일시정지 — 임시 (2026-10-26)

- 기획(9장 확정): 회의를 시작하면 게임 전체 시간이 멈추고, 모든 플레이어가 준비 완료하면 재개한다.
- 구조: 회의 상태(열림, 준비한 사람)는 호스트가 가진다(`MeetingSync`). 누가 T를 누르든 호스트가 모두에게 "열림"을 보내 각자 `get_tree().paused`로 멈추고, 준비 현황(몇 명 중 몇 명)을 모두에게 보낸다. 전원이 준비하면 모두에게 "닫힘"을 보내 0.25초 뒤 같이 재개한다. 혼자 플레이는 내가 준비하면 바로 재개한다. 일시정지 중에도 RPC는 도착한다.
- 기획 미정 사항의 임시 규칙:
  - 개시 권한: 누구나 연다. 이미 열려 있으면 무시한다.
  - 회의 중 가능한 행동: 지도 핑 찍기·지우기(D-018)와 준비 완료만. 준비 완료는 취소할 수 없다.
  - 연결 해제: 회의 중에 나간 사람은 준비 인원에서 빠진다. 남은 사람이 모두 준비했으면 바로 재개한다. 호스트가 나가면 기존대로 참가자는 시작 화면으로 돌아간다.
  - 횟수·시간 제한: 없다.
- 다시 볼 조건: 플레이테스트에서 회의 남용(적이 몰려올 때 멈추기) 문제가 보이면 횟수·쿨타임·개시 권한을 정한다.

## D-020 패시브 트리: 전투·생존·건설 3갈래 노드 — 임시 (2026-10-26, 갈래 구성은 사용자 결정 + 노드·수치는 임시)

- 결정(사용자): 경험치로 찍는 패시브(D-015)를 전투·생존·건설 3갈래로 나눈다. 전투는 "무기 종류별 강화"와 "순수 피해 증가"로 묶음을 나눈다. 노드형 그래픽은 아래 2026-10-26 적용 기록을 따른다. 생존·건설 노드 구성은 에이전트가 제안했다(임시).
- 데이터: `data/passives.gd`(PassiveDB). 노드마다 `branch`(combat·survival·building), `lane`(갈래 안 묶음 번호, `PassiveDB.LANES`), `pos`(갈래 격자 안 (열, 행), 행 0이 뿌리), `requires`(선행 노드 id 목록, 모두 1단계 이상이어야 찍음), `name`·`desc`·`costs`·`values`. 노드 그래픽은 이 값으로 배치·연결선을 그린다. 같은 갈래 안에서 `pos`는 겹치지 않고, 선행 노드는 항상 위 행에 있다(`tests/logic_test.gd`가 확인).
- 전투
  - 무기 숙련: 무기마다 숙련(그 무기 기본 공격 피해 +10/20/35%) → 특화. 검 휩쓸기(휘두르는 각도 +20/40도), 활 꿰뚫는 화살(관통), 석궁 속사(공격 속도 +15/30%), 지팡이 불씨 폭발(맞힌 적 주변 48/72px에 절반 피해). 무기 종류는 `ItemDB` weapon의 `family`(sword·bow·crossbow·staff).
  - 화력: 날카로운 일격(모든 기본 공격 +10/20/35%) → 마무리 일격(5/4/3번마다 한 번 피해 2배), 스킬 위력(장비 스킬 피해 +15/30%). 마무리 일격 → 처형자(체력 30% 이하 적에게 +25/50%).
  - 마무리 일격은 확률(치명타) 대신 횟수로 정했다. 결과를 정하는 무작위를 참가자 화면에서 굴리지 않기 위해서다(AGENTS 5절).
- 생존
  - 신체: 강인함(최대 체력) → 재생(3초 동안 안 맞으면 초당 1/2/4 회복) → 최후의 저항(쓰러질 피해를 체력 1로 버티고 2초 무적, 90/60초에 한 번). 강인함 → 빠른 복귀(부활 시간 -25/50%). 날렵함(이동 속도) → 질풍(대시 쿨타임 -20/40%).
  - 채집: 풍요로운 손 → 광역 채집, 큰 가방, 약탈자 → 보물 사냥꾼(상자 장비 확률 +10/20%p).
- 건설 (효과는 내가 짓거나 고칠 때 적용, 건물에 남는다)
  - 운영: 알뜰한 건축(건설 비용 -15/30%, 자원마다 최소 1개) → 긴 팔(건설 거리 +2/4칸), 탑 훈련(내가 지은 화살탑 공격 속도 +25/50%), 보수 전문가(핵 수리량 +50/100%).
  - 방벽: 튼튼한 기초(내가 지은 건물 체력 +25/50/80%) → 자가 보수(초당 1/2 회복), 가시 벽(때린 적에게 피해의 30/60% 반사, 처치 보상은 화살탑처럼 나눔). 자가 보수 + 보수 전문가 → 긴급 요새화(밤이 시작될 때 왕국 건물·핵을 최대 체력의 30/60% 회복, 한 명만 배워도 적용, 가장 높은 단계).
- 멀티플레이: 각자 배운 단계를 `PlayerSync`로 모두에게 보내고(`RemotePlayer.ranks`), 호스트는 `Main.passive_value(peer_id, id)`로 그 사람의 약탈자·보물 사냥꾼을 보상 추첨에, 건설 패시브를 `Kingdom.build(perks)`·`repair(bonus)`에 쓴다. D-017 2단계의 "참가자 약탈자 보너스 무시" 한계는 없어졌다. 전투·신체 패시브는 그 사람 화면의 공격·캐릭터에 적용되고, 참가자의 공격 값(관통·불씨·처형 포함)은 호스트가 다시 실행할 때 그대로 쓴다(피해 값을 믿는 D-017 한계와 같다).
- 이전 패시브 7종은 id·수치를 그대로 두고 트리에 넣었다. 광역 채집만 풍요로운 손이 선행으로 생겼다.
- 다시 볼 조건: 노드 그래픽이 들어올 때 `pos` 배치 조정, 플레이테스트 밸런스, 새 무기 종류 추가(숙련·특화 노드 한 쌍과 `FAMILY_MASTERY` 추가).

## D-021 보스 7종·최종 보스 승리·가파른 난이도 — 임시 (2026-10-26, 사용자 요청 + 패턴·수치는 임시)

- 요청(사용자): 21일차까지 보스를 만든다. 보스는 매번 다른 종류로 나온다. 패턴은 에이전트가 정한다. 난이도는 높게(상승폭 크게). 그래픽은 신경 쓰지 않는다.
- 보스 순서(3일마다 밤, `EnemyDB.BOSS_ORDER`): 3일 타락한 수호자 → 6일 늑대 군주 → 9일 독침 폭군 → 12일 서리 거신 → 15일 늪의 어머니 → 18일 화염 군주 → 21일 최종 보스 왕국 파괴자. 21일 뒤에도 보스 밤이 오면 최종 보스를 뺀 앞의 보스들을 다시 돌린다.
- 패턴(데이터 `patterns`, 무작위 없음): radial(원형 탄, 번갈아 반 칸씩 회전), spiral(여러 갈래 회전 연사), fan(가장 가까운 플레이어 조준 부채꼴), charge(멈춰서 번쩍이는 예고 뒤 돌진, 닿으면 큰 피해), summon(그날 침공 배율의 부하 소환, 살아 있는 수 상한). 체력이 줄면 `rage` 단계로 패턴 속도·이동 속도가 오른다(최종 보스는 60/30/10%의 3단계).
- 보스는 아침이 와도 사라지지 않는다(침공 일반 적·부하만 사라짐). 보스 체력은 보스마다 다르고(1,100 → 16,000) 플레이어가 한 명 늘 때마다 기본의 60%씩 더한다.
- 승리 조건(임시): 21일차 최종 보스를 쓰러뜨리면 승리 화면(멸망 화면과 같은 창, 제목 "승리!")이 뜨고 판이 끝난다. 판정은 호스트가 하고 참가자에게 같은 문장을 보낸다. 기획서의 "최종 보스 처치가 목표"를 따른 임시 규칙이며, 노션 #15(최종 보스와 승리 조건 기획)의 사용자 결정으로 바뀔 수 있다.
- 난이도(`Balance`): 침공 수 `6 + 4×일차 + 일차²/8`(상한 110, 18일차부터), 체력 배율 `1 + 0.22d + 0.012d²`(d = 일차-1, 21일차 약 10배), 피해 배율 `1 + 0.07d`(21일차 2.4배). 침공 구성은 일차별 가중치로 슬라임이 줄고 2일 고블린, 3일 거인, 5일 늑대, 6일 전갈, 8일 늪 슬라임, 11일 화염 정령이 섞인다. 낮 배회 적도 체력 `1 + 0.1d`·피해 `1 + 0.04d`로 강해진다.
- 그래픽(임시): 보스 7종은 기존 보스 그림 한 행을 `tint` 색만 바꿔 같이 쓴다. 참가자 화면도 같은 색으로 그린다.
- 멀티플레이: 보스 AI·패턴은 호스트에서만 돈다. 탄은 기존 `enemy_shot` 복제로, 부하는 기존 적 동기화로 참가자에게 보인다. 회전 연사는 탄마다 RPC를 보내므로(최대 초당 64발) 실제 Steam 연결에서 부하를 확인해야 한다.
- 다시 볼 조건: 플레이테스트로 보스 체력·침공 수(성능 포함) 조정, 보스 전용 그림, 사용자의 최종 보스·승리 조건 결정.

## D-022 건설 메뉴 3분류·벽 테크·공성탑·생활 건물·순간이동 탑·새 자원 — 임시 (2026-10-26, 사용자 요청 + 건물·수치는 임시)

- 요청(사용자): B 메뉴를 벽·공성타워·생활로 나눈다. 제작대는 왕국에 하나만. 생활에 순간이동 탑 같은 유틸: 모든 탑이 연결되고, 상호작용하면 지도가 나오고, 외부에 설치한 탑으로 이동한다. 순간이동 탑은 왕국 밖에도 짓는다. 벽 테크·자원 종류·공성탑 종류·생활 건물은 에이전트가 정한다.
- 구조: `BuildingDB`의 `category`(wall·siege·utility)로 탭을 나누고, `tier`(필요한 제작대 단계)로 테크를 잠근다. `Kingdom.tech_error()`가 건설 메뉴 잠금 표시와 `build()` 검증을 같이 맡는다. `outside`인 건물만 왕국 영토 밖에 지을 수 있다.
- 벽 7종: 나무벽·돌벽(0단계), 가시 목책(1, 때린 적에게 50% 반사)·단단한 목벽(1), 철벽(2), 흑요석 성벽(3), 정수 방벽(3, 보스의 정수, 초당 4 회복).
- 공성탑 6종: 화살탑(0), 발리스타(1, 관통·장거리 고피해), 대포탑(2, 맞힌 자리 72px 범위 절반 피해), 서리탑(2, 2초간 속도 45%), 화염탑(3, 초근거리 고속 관통 연사), 번개탑(3, 보스의 정수, 3갈래).
- 생활 6종: 장비 상자, 제작대(하나만), 순간이동 탑(1, 밖 가능), 모닥불(0, 밖 가능, 3칸 안 초당 체력 3), 보급소(1, 밖 가능, 근처에서 가방 자원이 창고로 입고), 감시탑(0, 밖 가능, 지을 때 주변 18칸 지도 탐험).
- 순간이동 탑: 모든 탑이 연결된다. 탑 옆에서 E → 지도(탑은 보라색 마름모)와 목적지 목록. 지도에서 탑 근처를 누르거나 목록에서 고르면 그 탑 아래로 이동한다. 이동은 각자의 캐릭터가 정한다(D-017). 출발 탑 옆에 있고 목적지가 아직 탑일 때만 이동한다. 왕국 핵은 목적지가 아니므로 왕국 안에도 탑을 하나 짓는 것을 전제로 한다.
- 새 자원 3종: 석탄(구리·철 광석 채집 시 +1), 송진(단단한 나무 채집 시 +1), 보스의 정수(보스를 잡으면 왕국 창고로 1개, 최상위 벽·탑 재료). 장비창·HUD 재료 목록 뒤에 붙였고 아이콘 그림은 아직 없다.
- 그래픽(임시): 새 건물은 원래 건물 그림 칸(나무벽·돌벽·화살탑·장비 상자)에 `tint` 색만 입힌다. 멀티플레이 참가자 화면도 같은 색이다.
- 다시 볼 조건: 건물 전용 그림·자원 아이콘, 플레이테스트로 비용·체력·탑 수치 조정, 순간이동에 쿨타임·비용이 필요한지.

## D-023 손맛·연출: 피해 숫자, 화면 흔들림, 멈칫, 보스 체력바·배너, 침공 예고 — 임시 (2026-10-26)

- 피해 숫자: 적이 피해를 받을 때마다 `Events.damage_dealt`. 패시브로 강해진 공격(마무리 일격·회오리 베기·처형자·선제공격)은 강조(크게, 주황, "!"). 호스트는 숫자를 적 모습과 함께 0.1초마다 최대 48개씩 묶어 참가자에게 보낸다(unreliable, 넘치면 버림 — 연출일 뿐).
- 화면 흔들림: `Events.screen_shake_requested(위치, 세기)`. 각자 화면에서 내 캐릭터와의 거리(640px)만큼 약해진다. 폭발 7, 대포탑 범위 피해 2.5, 보스 돌진 6, 보스 처치 12(거리 무관). 호스트가 참가자에게 전한다.
- 멈칫(히트스톱): 강조 공격 0.05초, 보스 처치 0.15초 동안 게임 속도를 5%로. `Engine.time_scale`은 호스트 게임 전체를 바꾸므로 **혼자 플레이에서만** 한다.
- 보스 연출(`ThreatBanner`): 살아 있는 보스가 있으면 화면 맨 위에 이름과 큰 체력바, 처음 보이면 가운데에 "보스 등장 / 최종 보스" 배너. 호스트는 `Enemy`, 참가자는 `EnemyPuppet`에서 읽는다(`Main.boss_status()`). HUD 알림은 그 아래(60px)부터 쌓인다.
- 침공 예고: 밤까지 15초 이하면 "침공까지 N초 · 적 약 N마리 · 오늘 밤 보스: 이름". 적 수·보스는 일차로 정해지는 값이라 무작위가 아니다(실제 구성은 호스트가 굴린다).
- 다시 볼 조건: 플레이테스트에서 숫자가 너무 많아 화면이 지저분하면 작은 숫자 합치기·끄기 옵션, 흔들림 세기 조정.
